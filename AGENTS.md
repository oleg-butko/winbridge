# WinBridge: инструкции для агента

## Начало сессии

1. Прочитать `README.md`, `docs/handoff.md`, `docs/architecture.md`, `docs/roadmap.md` и `docs/ux.md`.
2. Выполнить `git status --short`, сверить фактический код с таблицей готовности в handoff.
3. Взять первый незавершённый этап roadmap. Завершать небольшие вертикальные сценарии с реальным исполнением и видимым результатом.
4. Документ `docs/context/original-proposal-2026-10-04.md` — история обсуждения. Его TLS и единый workspace с Netwatch отменены последующими решениями пользователя. Текущие решения находятся в architecture и ADR.

## Принятые решения пользователя

- Отдельный репозиторий `/home/user1/winbridge`; Netwatch находится в `/home/user1/netwatch`.
- Работа полностью локальная: Windows host и Debian VM в VMware. Шифрование соединений не требуется. Использовать `ws://`; не добавлять TLS, сертификаты, VPN, SSH или удалённый relay без новой задачи пользователя.
- Общая папка `/mnt/hgfs/shared` соответствует `K:\VMs\shared` на Windows. Она служит для доставки готовых снимков. Сборка выполняется в отдельной папке Windows.
- Агент может использовать рецепты и произвольные команды внутри зарегистрированной папки проекта.
- Подробный UI/UX и прозрачность каждого действия — обязательная часть функции, а не завершающая косметика.
- Команды, output, ошибки, отмена и восстановление должны быть видны пользователю; UI не подменяет реальное состояние оптимистическими сообщениями об успехе.

## Границы компонентов

- `crates/protocol` — версия протокола и DTO. Это источник контрактов для Rust и будущей генерации TypeScript.
- `crates/core` — логика задач и проектов, policy и interfaces обработчиков; без Tauri и HGFS путей.
- `crates/transport` — будущее место WebSocket, local IPC и восстановления сессий.
- `crates/platform` — будущие Windows/Linux операции с процессами и файлами.
- `apps/controller` — Debian coordinator и вход для CLI/MCP.
- `apps/worker` — Windows execution authority, очередь, журнал и владение процессами.
- `apps/desktop` — будущий Tauri shell, пользовательский tray и уведомления.
- `modules` — sync, runner, log reader, attention; возможности подключаются статически.
- `ui` — React/Mantine. Браузерная демонстрация не выполняет команды; настоящее IPC добавляется отдельным этапом.

Не копировать Netwatch целиком и не добавлять зависимость на соседний каталог. Любой перенос кода из Netwatch сопровождать проверкой его контракта и сохранением существенных тестов.

## Работа с файлами и безопасностью

- До первого изменения или удаления важного файла, состояние которого не восстановить из Git, выполнить `/home/user1/.local/bin/codex-backup <path>` и проверить результат. Это относится и к tracked файлам с пользовательскими правками.
- Делать один снимок исходного файла на задачу. После изменения валидировать файл и сообщать путь бэкапа и точную команду восстановления.
- Не менять ничего в `/home/user1/backup`. Исключение — явно запрошенная пользователем операция; создание снимка штатной командой выше предусмотрено правилом.
- Не создавать plaintext копии credentials, `.env`, ключей или authentication stores. Для них сначала согласовать encrypted backup workflow. SQLite копировать через consistent backup API.
- Не коммитить runtime config, secrets, базы, output или logs. Использовать `config.example.json` и fixtures.
- Не менять VMware, mounts, firewall, systemd, Windows services или глобальную конфигурацию инструментов без отдельного разрешения.
- Shared Folders содержат пользовательские данные: изменять только namespace и файлы WinBridge, на которые дано разрешение. Обнаружение mount не даёт разрешения на запись или очистку общего каталога.
- `cwd` не является sandbox. Проверять project scope, traversal, junctions, symlinks и зарезервированные Windows пути; доверенная сборка выполняется с правами пользователя.

## Исполнение и достоверность

- Worker хранит accepted task до ACK. Повтор idempotency key не создаёт новый процесс.
- После неизвестного исхода внешней команды сообщать `indeterminate`, не перезапускать её автоматически.
- Одновременно читать stdout и stderr; медленный UI не должен блокировать процесс.
- Отмена касается управляемого дерева процессов. Закрытие UI и разрыв WebSocket не отменяют принятую задачу.
- Публикация snapshot начинается с staging и завершается verified manifest/ready marker. Не собирать из изменяющегося shared каталога.
- Журнал SQLite и Windows build caches хранить на локальном диске, не в HGFS.

## Проверки и стиль

Rust 2021, `cargo fmt --all`; TypeScript strict, отступ 2 пробела. Запускать проверки, соответствующие изменениям. Тестировать реальные риски: дубли запросов, crash recovery, тайм-ауты, отмену дерева, traversal, неполную передачу и потерю mount.

Текущие команды: `cargo test --workspace --locked`, `cargo check --workspace --locked`, `cargo fmt --all -- --check`, `npm ci`, `npm run check:scaffold`, `npm run typecheck`, `npm run build:ui`. UI/browser demo не заменяет Windows проверку реального исполнения.

В этой Debian среде Rust wrappers находятся в `/home/user1/.local/bin`. При отсутствии cargo использовать `PATH=/home/user1/.local/bin:$PATH cargo ...`; startup файлы оболочки не менять. Windows target доступен для `cargo check --workspace --target x86_64-pc-windows-msvc --locked`, но это не выполнение Windows программы.

Коммиты Conventional Commits. Перед фиксацией обновлять roadmap/handoff при изменении готовности. Не записывать незавершённые возможности как реализованные. Даты в документах отражают сессию; UTC timestamp бэкапа может быть на следующий день относительно America/New_York.
