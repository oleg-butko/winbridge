Следующий обязательный gate после
[Main25](main25-after-multi-controller-2026-10-27.md). Это отдельная проверка данных,
не повтор Main24 и не попытка обновить installed runtime. Исторический

## Реализация

- `apps/update/tests/activation_service_migration.rs`: ignored native test с
  отдельным `WINBRIDGE_SERVICE_MIGRATION_INPUT`, fixed19→20 contract.
  Query/inspect actual retained19 image + manifest + physical6 + confirmed writer1
  и root. SQLite Backup API копирует journal в новый isolated runtime.
  Normal migration делает schema20, fencing epoch+1 и consistent migration backup.
  Полный row digest всех старых таблиц (включая keys/history/writer) сохраняется;
  исключены только installation и три конкретные новые service tables, не prefix.
  Все новые service tables пусты. Cold replacement lookup возвращает Existing,
  сохраняет physical/writer/root; получение owner для этого чтения отдельно
  отражено как `afterColdObservation` с ещё одним epoch. Свежих permits нет.
  Old19 `journal init/status` отказывают UnsupportedSchema без изменения копии.
  Исходные DB/WAL bytes, manifest/image identities неизменны.
- `scripts/test-update-service-migration.ps1`: source/reference hash checks,
  free≥6GiB, тот же build-cache lease, exact single ignored test, отчёт/ready files.
  Worker/desktop не запускаются, UI и сеть не нужны. Ничего не очищается.
- `scripts/run-update-service-migration-native.py`: новая create-only задача через
  установленный worker. До dispatch: clean verified archives со schema20/19/19,
  старый terminal task, pinned old report/proof, full readonly writer/replacement
  audit. После: result bytes twice, exact Cargo/libtest selection, независимый
  migration audit21 mutations и installed identity/health/active0 readback.
- `scripts/verify-update-service-migration-native.py`: тот же независимый audit
  можно повторить только по сохранённому run-info и трём exact archives, без
  Windows RPC и без повторного выполнения задачи. Terminal reference/request/
  acceptance и обе пары source pins сохраняются до проверки.
- `scripts/update-activation-service-migration-proof.py` и regression suite:
  сравнение с предварительно проверенным old reference, typed counters/flags,
  запрет invented grants/private identities, старый root не relabelled как готовый.

Source проверки: MSVC Clippy нового native target; Python4/0,21 negative mutations
на synthetic fixture; py_compile/help/fmt. Это ещё **не actual migration proof**.
Во время подготовки выполняется новый Main25 e03bb2a, новые migration файлы в его
producer отсутствуют; результаты сценариев не смешивать.

## Запуск

После завершения Main25, clean commit/export и восстановления двух старых ZIP:

```bash
python3 scripts/run-update-service-migration-native.py \
  --source-archive /mnt/hgfs/shared/WinBridge/sources/NEW-CLEAN-ARCHIVE.zip \
  --reference-source-archive /mnt/hgfs/shared/WinBridge/RECOVERED/winbridge-20261025T232727Z-acf7123-7d95795d.zip \
  --reference-target-archive /mnt/hgfs/shared/WinBridge/RECOVERED/winbridge-20261025T232657Z-2413653-bf3f5db3.zip \
  --reference-run 20261025-232746-26bad6d7 \
  --reference-task-id a49ade1f-4e35-4eff-84ac-3b8d21c0a9ea \
  --reference-report-sha256 f5ed30fb6bfcac8df37d9584aef22d4f2dc644ba66774bb1e5d8cd08c28eecde \
  --reference-proof-sha256 b71a98c2d6cf41d1c4895d223fe12eb1a34eaa3c4c44ab7157bf1eaeabda34df \
  --cache-run 20261017-061527-f4639971 \
  --controller-config .winbridge/controller-snapshot.local.json
```

Только installed worker должен работать, desktop можно закрыть, окон не будет.
При потере ответа читать acceptance/run-info/request и тот же task ID/key;
не отправлять неизвестную попытку заново. После terminal оставить рабочий worker.
Далее — controller confirmation/lifetime/commit/scoped release, затем U2–U4.
