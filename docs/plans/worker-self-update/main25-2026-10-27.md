## Изменения сценария

Добавлен отдельный ignored native Main25 test в `update_shutdown`. После StateOwned
он немедленно отправляет writer24, после Confirmed — service25, намеренно теряя
только ответы этих стартовых команд. До этих отправок нет тяжёлых DB/hash audits.
Последующие запросы наблюдают тот же attempt. Проверяются actual process stamp/
Job/instance lock, activation7/LocalVerified и root AwaitingController, один epoch+1,
writer/service history, authenticated normal IPC, task/output и отказ новых команд.
До обновления через настоящий Worker устанавливается пользовательская pause;
сервис должен сохранить её receipt и запретить resume. Проверяются image sharing,
повтор service start, actual Job exit и cold NotResident без нового запуска.

Private normal-Main driver перед supervisor admission ждёт настоящий свежий handshake
с predeclared controller1144 до900s. Это отдельное ожидание файервола, без открытия
второго Store или изменения первоначального activation budget240s. URL остаётся
в frozen config. После локальной активации он должен быть виден, но session и
connector ещё отсутствуют. Debian fixture controller должен оставаться доступным.

`test-update-health-actor.ps1 -ActivationServiceGate` получает FixtureInstanceId,
FixtureControllerUrl, TestRuntimeDirectory и InstalledWorker. После old-role build
собирается точный validation worker; только затем original script reservation
фиксирует его SHA и постоянный exe path, до config/manifest/baseline. Script lease
остаётся открытым до native Main completion и архивирования по retirement proof.
Нет exit proof — файлы сохраняются и slot блокируется. Cold JSON не заменяет lease.

Main25 использует новый proof kind. Старые Main24 проверки сохраняют прежнюю фазу;
новый cold replacement audit ожидает AwaitingController. В этом режиме старые
18→19/16→17 migration tests намеренно не подменяют обязательный будущий19→20 gate;
report явно отмечает `migrationChecked=false`.
