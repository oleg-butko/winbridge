# Private service4: sender, receiver и независимый normal IPC

2026-10-26. Продолжение [общего Worker/local IPC](local-service-runtime-2026-10-26.md).
Рабочий worker0.1.1/source59249e6 остаётся установленным. Новая реализация —
trusted library/internal receiver, не включённая публичная установка.

## Реализованный путь

- Private V4 `ActivationReceiverServiceCommand/Ready` и отдельный marker
  `WINBRIDGE_PRIVATE_LOCAL_SERVICE_V4`; формы V1/V2/V3 не меняются.
  Service Ready — сигнал для независимого чтения, не достаточное health proof.
- `UpdateJournal::inspect_activation_service_receiver` читает confirmed writer,
  service Issued, accepted shutdown, current root/owner/supervisor и physical
  StateOwned6 в одной readonly transaction. Повторный обход полного графа не
  требуется: shared writer helper проверяет custody в том же snapshot. История,
  Indeterminate/Confirmed service и pre-migration activation не дают startup.
- `apps/worker/src/activation_service.rs` продолжает тот же authenticated канал
  после writer ACK, потребляет тот же ActivationJournal/Fresh и передаёт их
  LocalService. Parent/runtime/graph и исходный monotonic deadline проверяются
  в checkpoints; новый timeout для admission не создаётся. Config pins живы
  весь receiver lifetime. Повторное открытие Store/lock или новый epoch отсутствуют.
- После bind receiver сам читает нормальный IPC с проверкой server PID и только
  затем отправляет Ready. Он сохраняет resident verification ownership до
  закрытия канала/parent exit/ограниченного hold; последующий controller/lifetime
  требует отдельного контракта. Перед выходом local service останавливается/join.
- `ActivationServicePreparation::start_local_service_blocking` потребляет fresh
  permit, делает одну V4 send на исходном IO driver, проверяет private Ready,
  затем отдельно читает нормальный IPC. Успех сохраняет service Confirmed и
  возвращает исходный process guard. Это пока не activation7/root LocalVerified,
  Committed, release maintenance или перенос Job lifetime.
- V4 marker проверяется до service admission. Неизвестный результат send/read/
  commit не вызывает replay. Ошибка сохраняет custody и по возможности помечает
  service/activation indeterminate. Даже отсутствие исходного IO runtime после
  admission не оставляет permit для будущего повторного send.

## Readonly observation на обычном IPC

`ActivationServiceQuery`/`ActivationServiceObservation`, version1, — отдельный
локальный envelope, не worker/controller RPC или MCP action. Он работает только
в staged local mode. Worker хранит immutable resident binding вместо отдельного
boolean; присланная команда обязана полностью совпасть с ним. Другой binding,
версия, обычный Worker или fixture без настоящего RuntimeGuard получают Rejected.

Receipt собирается из actual RuntimeGuard, проверенных config bytes, текущей
worker authority/schema, actual updater schema, instance/context/generation и
сохранённого quiesced shutdown/lease. Нельзя вернуть присланную identity как
доказательство actual runtime. Readonly наблюдение допустимо после startup
window: это поздний факт, а не новый grant, send или продление срока.

Parent `activation/service_probe.rs` аутентифицирует server PID, сверяет этот
receipt и normal Info (build/platform/context/generation, absence fresh controller
session, disabled mutations/maintenance/snapshot/workflow, zero active tasks,
Quiesced readonly lease). Затем читает task history и при наличии task её detail/
output. Full Main25 fixture должна отдельно сравнить ожидаемое прежнее содержимое.
Private Ready или mock response не заменяют эту полную интеграционную проверку.

Structured timings `receiver_service` и `service_delivery` отмечают исходный
remaining deadline, startup/bind/normal IPC и durable confirmation. Никакие nonce
или config contents не выводятся.

## Следующий обязательный шаг

1. Перед любым full gate проверить V4 marker candidate ДО controlled shutdown;
   отсутствие новой capability не должно обнаруживаться после остановки старого
   worker. Actor25/view17: отдельные start/observe service actions, one resident Written
   guard → busy service → owned service либо retained failure. Ни cold record,
   ни volatile ACK не объявляют живой локальный сервис. Сохранить views1–16 и
   contracts1–24 frozen. Подключить typed service view к schema20 ledger.
2. Только под тем же resident original guard после normal-IPC confirmation:
   activation7/root LocalVerified. Сохранённые facts не восстанавливают custody.
3. Новый Main25: реальный old worker shutdown → final backup → replacement →
   тот же child/lock → writer → V4/normal service → старые task/output, blocked
   roots/queue и configured-but-disconnected controller → duplicate/lost ACK/
   cold observe → actual process/Job exit. Все проверки через работающий worker,
   без новой установки. Migration/refusal19→20 на retained consistent copies
   остаются отдельным обязательным proof.
4. Затем реальная controller session (заранее предусмотреть постоянный network
   activation test slot), durable Job lifetime transfer, commit/scoped maintenance
   release, remaining U2/U3/U4. Public install не включать до этих gates.
