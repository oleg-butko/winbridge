## Выбранное направление: release desktop

Следующий большой расход — ~112s release desktop на snapshot, два таких build
в полном native gate. Проверяем гипотезу: уменьшить opt-level локальных desktop
crates с3 до1, оставив release-режим, custom-protocol и остальные compiler flags.
Registry dependencies остаются opt3. Local packages: desktop/core/protocol/
platform/transport. Фактические opt/debug/assertions/overflow flags проверять по
Cargo JSON. Это не изменение рабочего installed runtime.

План A/B: каждый trial распаковывает один и тот же clean ZIP в новую локальную
папку с manifest verification. Поэтому локальные crates должны действительно
компилироваться заново у обеих сторон; dependency cache и эксклюзивный lease
общие. Никаких clean/touch/удаления cache или изменения snapshot для force rebuild.
Первый A и B — warmup; далее ABBA. Clone/verification time записывать отдельно
от Cargo wall. Списки compiled local crates, profiles и source identity должны
совпасть по смыслу. После каждого build — frozen payload copy и managed
artifact-query через pinned updater, без UI и конфигурации.

Заранее выбран критерий pilot: median Cargo wall ниже минимум на20% и30s,
обе пары быстрее, spread каждой стороны <=20%, все identity/source/cleanup checks
passed. При шуме или меньшем эффекте продолжить измерения/изменить гипотезу;
не выдавать подготовку за результат. Даже положительный pilot требует полного
native gate с новым profile перед рекомендацией. Release assertions/overflow
должны остаться теми же, что у control; не ослаблять дополнительные guards.
