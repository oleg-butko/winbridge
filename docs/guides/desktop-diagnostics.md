# Если desktop не скрывается или не завершается

Desktop запускается без параметров: `K:\_proj-26\winbridge\runtime\winbridge-desktop.exe` читает `winbridge-desktop.local.json` рядом с exe. Крестик и «Скрыть в tray» сохраняют формы и скрывают окно; «Завершить интерфейс» завершает desktop. Worker работает независимо.

После исправлений от 2026-10-10 у desktop есть собственный журнал. Старые сборки его не создают, поэтому прежний случай по этому журналу восстановить нельзя.

## Что делать, если кнопка не сработала

Посмотрите сообщение рядом с блоком tray. Несохранённый конфиг нужно сохранить или отменить в «Проекты, соединение и хранение». Добавление проекта и последующее удаление того же проекта восстанавливают исходный JSON и больше не оставляют ложную правку из-за форматирования.

Если сохранение формы не подтвердилось за 10 секунд, окно остаётся открытым, а кнопки снова доступны. Запись может продолжаться; её позднее завершение само окно не закрывает. Можно повторить закрытие или явно выбрать «Закрыть без сохранения». Эта кнопка допускает потерю несохранённых полей. При отсутствии ответа на native-закрытие также появляется сообщение через 10 секунд: запрос мог уже быть принят.

В popup «Скрыть» скрывает только уведомление. Событие остаётся непрочитанным до отдельного «Прочитано». Ошибка или отсутствие ответа показываются внутри popup; кнопка становится доступна для повторной попытки.

## Какой журнал передать агенту

Для постоянного runtime путь такой:

```text
K:\_proj-26\winbridge\runtime\logs\desktop.jsonl
```

Путь также показывается в блоке tray. При другом расположении exe журнал находится в его подпапке `logs`. Один файл ограничен 1 MiB; сохраняются пять предыдущих файлов `desktop.1.jsonl` … `desktop.5.jsonl`, всего до 6 MiB. События пишутся автоматически, отдельный режим диагностики не нужен.

Журнал содержит время, PID и идентификатор запуска, нажатия close/hide/quit и popup, источник действия (окно, tray или кнопка), начало/результат сохранения, отказ и тайм-аут. Каждые 10 секунд отдельно проверяются WebView и обработка native-очереди. Эти записи помогают отличить запрет закрытия от ожидания сохранения и остановки native-обработки. Значения полей, команды, аргументы и stdout/stderr сюда не записываются.

Запись идёт через ограниченную очередь в отдельном потоке. Если диск недоступен или очередь переполнена, интерфейс показывает ошибку журнала или число потерянных записей; полнота лога в таком случае не гарантируется.

После повторения проблемы запомните примерно время и последовательность действий. Завершите desktop; если потребовалось остановить его через диспетчер задач, это тоже укажите. Worker оставьте работать. Затем в PowerShell скопируйте журналы в новый общий каталог:

```powershell
$run = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$destination = Join-Path 'K:\VMs\shared\WinBridge\desktop-diagnostics' $run
New-Item -ItemType Directory -Path $destination -ErrorAction Stop | Out-Null
Get-ChildItem -LiteralPath 'K:\_proj-26\winbridge\runtime\logs' -Filter 'desktop*.jsonl' -File |
    Copy-Item -Destination $destination -ErrorAction Stop
$destination
```

Передайте имя этого каталога и описание действий. Агент прочитает файлы из `/mnt/hgfs/shared/WinBridge/desktop-diagnostics/<run>`. Копирование после завершения desktop даёт стабильные файлы; после принудительной остановки последняя строка может быть неполной. Конфиги и файл состояния desktop для этого сбоя передавать не требуется.

## Автоматическая проверка

`validate-workflow-native.py --companion-only` проверяет реальную Windows сборку в отдельном runtime: отмену добавления проекта, отсутствие save ACK и восстановление кнопок, позднее подтверждение без скрытия окна, hide/reopen/quit и кнопку «Скрыть» в popup без подтверждения события. Сценарий сохраняет desktop JSONL вместе с проверенными отчётами. Рабочий runtime и пользовательские настройки не заменяются.
