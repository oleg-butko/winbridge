# Общий лимит работ — A4.1

Кандидат 2026-10-15 прошёл [57 native Windows tests и desktop check](../plans/architecture-transition/windows-work-scheduling-gate-2026-10-15.md).
Новая установленная Windows версия ещё ожидается; текущие рабочие настройки
не изменены. [Порядок обновления](../validation/architecture-worker-update.md).

WinBridge может ограничивать число одновременно исполняемых команд и импортов
во всех проектах. Без настройки сохраняется прежний режим: один изменяющий
исполнитель на проект, общего лимита нет.

В локальном worker config новый раздел выглядит так:

```json
"workScheduling": { "maxConcurrentWork": 2 }
```

Это фрагмент корневого JSON объекта, допустимы значения 1..32. Он применяется
после обычного ручного restart worker. Пока производственное значение не выбрано
пользователем, раздел остаётся отсутствующим. Агент через MCP не передаёт свой
лимит и не меняет политику в работающем worker.

Когда слотов недостаточно, принятые задачи остаются queued и показывают причину
«Общий лимит работ: занято …». Отмена и чтение результатов доступны. Неопределённое
завершение сохраняет занятость, пока физическое освобождение не подтверждено.

| Что выполняется | Учёт work slot |
| --- | --- |
| Обычная команда, импорт | Один слот на активную project mutation lease |
| Workflow | Слот исполняющегося child, без второго слота для parent |
| Готовое приложение | Освобождает work slot, сохраняет application lifetime lease |
| Неопределённый прежний исполнитель | Занимает слот до physical reconciliation |

Готовые проекты выбираются по последней сохранённой выдаче ресурса: недавно
работавший проект уступает другим готовым. Недоступный проект не задерживает
остальные. Сохранённые execution attempts удерживают этот порядок после restart;
системные часы его не задают. Внутри прежних классов очереди порядок сохраняется.

В UI блок «Общая нагрузка» показывает budget, занятые слоты и ожидающие операции.
Ожидание включает queued команды/импорты и queued workflow roots до создания child;
после запуска root ожидание его шага считается по child. Значения читаются вместе
из SQLite; дата среза и потеря свежей связи видны отдельно. Общий журнал содержит
причины и владельцев ресурсов. MCP получает те же сведения в
`winbridge_info.info.contractCatalog.workScheduling`; typed support объявлен как
`winbridge.work-scheduling` v1. Unknown/future metadata не подтверждает лимит.

Budget ограничивает работы WinBridge, а не загрузку CPU или все процессы Windows.
Отдельные ограничения приложений, binary/cache/IPC/ports/desktop, pause и backlog
входят в следующие пакеты A4. Их поддержка пока не заявляется.
